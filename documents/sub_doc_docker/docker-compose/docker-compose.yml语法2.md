`docker-compose.yml` 的核心是围绕 Compose 应用模型展开的，它通过一系列**顶层元素**来定义应用的骨架，再通过**服务级关键字**来描述每个容器的具体行为。

### 🏗️ 顶层元素：定义应用的骨架

顶层元素是 Compose 文件的根，用于定义应用的全局结构和共享资源。

| 元素 | 作用与用法 |
| :--- | :--- |
| **`name`** | **项目名称**。用于为整个应用命名，并作为资源（如网络、卷）的前缀，以隔离不同项目。可通过 `-p` 或 `COMPOSE_PROJECT_NAME` 环境变量覆盖。 |
| **`include`** | **模块化引入**。将一个或多个外部 Compose 文件作为独立子项目加载，非常适合按团队或功能组织大型项目。 |
| **`services`** | **服务定义（必需）**。这是 Compose 文件的核心，一个映射（map），其键是服务名，值是服务定义。 |
| **`networks`** | **自定义网络**。定义可被多个服务共享的网络，用于服务间的通信和隔离。 |
| **`volumes`** | **命名卷**。定义可被多个服务共享的持久化数据卷，用于数据存储和备份。 |
| **`configs`** | **非敏感配置**。定义或引用配置数据，以文件形式挂载到容器中，无需重建镜像即可调整服务行为。 |
| **`secrets`** | **敏感数据**。定义密码、证书等敏感信息，以文件形式安全地挂载到容器中，避免在环境变量或镜像中泄露。 |
| **`version`** | **（已废弃）**。在 Compose v2 中已不再需要，Compose 会自动使用最新的规范。 |

### ⚙️ 服务级关键字：定义容器的行为

`services` 下的每个服务都通过一系列关键字来配置其容器的行为。

#### 构建与镜像

| 关键字 | 作用与用法 |
| :--- | :--- |
| **`image`** | **指定镜像**。定义服务使用的镜像，可以是 Docker Hub 上的镜像或本地构建的镜像。 |
| **`build`** | **构建镜像**。定义如何从 Dockerfile 构建镜像。常用子键包括 `context`（构建上下文路径）和 `dockerfile`（Dockerfile 文件名）。 |
| **`pull_policy`** | **拉取策略**。控制 Compose 何时尝试拉取镜像，可选值如 `always`、`never`、`missing`、`build` 等。 |
| **`platform`** | **指定平台**。设置服务运行的目标平台，例如 `linux/amd64`。 |

#### 启动与命令

| 关键字 | 作用与用法 |
| :--- | :--- |
| **`command`** | **覆盖 CMD**。覆盖 Dockerfile 中定义的默认命令。 |
| **`entrypoint`** | **覆盖 ENTRYPOINT**。覆盖 Dockerfile 中定义的入口点。 |
| **`working_dir`** | **工作目录**。设置容器内的工作目录。 |
| **`user`** | **运行用户**。指定运行容器内进程的用户或 UID:GID。 |
| **`depends_on`** | **依赖关系**。控制服务的启动和关闭顺序。可配合 `healthcheck` 使用条件等待，确保依赖服务真正就绪。 |
| **`restart`** | **重启策略**。定义容器退出时的重启行为，例如 `unless-stopped`、`on-failure` 等。 |

#### 网络与端口

| 关键字 | 作用与用法 |
| :--- | :--- |
| **`ports`** | **端口映射**。将容器端口映射到主机，支持短语法（`"8080:80"`）和长语法（可指定协议、模式等）。 |
| **`networks`** | **接入网络**。指定服务连接到哪个（些）网络，需在顶层 `networks` 中定义。 |
| **`network_mode`** | **网络模式**。使用与 `docker run --network` 相同的值，如 `host`、`none`、`service:name` 等。 |
| **`expose`** | **暴露端口**。仅将端口暴露给链接的服务，而不发布到主机。 |

#### 存储与数据

| 关键字 | 作用与用法 |
| :--- | :--- |
| **`volumes`** | **挂载卷**。将宿主机路径或命名卷挂载到容器。支持短语法和长语法，长语法可指定类型（`volume`、`bind`、`tmpfs`）和读写权限。 |
| **`configs`** | **挂载配置**。将顶层定义的 `configs` 以文件形式挂载到容器中。 |
| **`secrets`** | **挂载机密**。将顶层定义的 `secrets` 以文件形式挂载到容器中。 |

#### 环境与配置

| 关键字 | 作用与用法 |
| :--- | :--- |
| **`environment`** | **环境变量**。直接在服务中设置环境变量，可使用映射或数组语法。 |
| **`env_file`** | **环境变量文件**。从文件中加载环境变量。 |
| **`labels`** | **元数据标签**。为容器添加元数据，建议使用反向 DNS 表示法以避免冲突。 |

#### 健康与资源

| 关键字 | 作用与用法 |
| :--- | :--- |
| **`healthcheck`** | **健康检查**。定义检查容器是否健康的命令和参数（如 `interval`、`timeout`、`retries` 等）。 |
| **`deploy`** | **部署配置**。主要用于 Swarm 模式。在单机 `docker compose up` 中，仅 `resources.limits` 和 `resources.reservations` 生效。 |
| **`shm_size`** | **共享内存大小**。设置容器的 `/dev/shm` 分区大小，对于 PostgreSQL 等数据库很重要。 |

### 💡 补充说明

*   **YAML 锚点与别名**：可利用 YAML 的 `&`（锚点）和 `*`（别名）以及 `<<`（合并键）来复用配置块，实现 DRY（Don't Repeat Yourself）原则，减少重复配置。
*   **扩展字段**：以 `x-` 开头的顶层字段会被 Compose 忽略，常用于结合锚点定义可复用的配置片段。
*   **变量插值**：Compose 文件支持使用 `${VARIABLE}` 语法进行变量插值，可通过 `.env` 文件或环境变量提供值，增加配置的灵活性。

掌握这些关键字后，你就可以根据应用的架构和需求，灵活地编写 `docker-compose.yml` 文件了。如果你对某个特定关键字（比如 `deploy` 或 `healthcheck`）的详细用法感兴趣，我们可以继续深入探讨。
